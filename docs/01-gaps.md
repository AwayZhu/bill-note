## A 类：只有你能答（影响做不做什么）

请直接回复编号 + 你的选择，例如"1要 2不要"。

| # | 问题 | 为什么影响架构 |
|---|------|--------------|
| A1 | **要分账户吗？**（现金/微信/支付宝/银行卡/信用卡分开记） | 分账户才有"余额"和"转账"概念，数据模型多一张表、多一种交易类型。这是 MVP 里最大的一个分叉 |
| A2 | **要预算吗？**（月度总预算 / 按分类预算） | 需要预算表和月度快照逻辑，中等成本 |
| A3 | **要固定收支提醒吗？**（房租、会员订阅每月自动记 + 通知） | 要用到系统通知权限和定时任务，成本中等偏高 |
| A4 | **要借还 / 应收应付吗？**（别人欠你钱、你欠别人） | 又一个独立实体，MVP 建议不做 |
| A5 | **要 AA / 多人分摊吗？** | 记账 App 里复杂度最高的一块，强烈建议不做 |
| A6 | **要报销 / 可抵扣标记吗？** | 只是交易上的一个标记字段，成本极低，可顺带 |
| A7 | **多币种吗？** | 涉及汇率来源，而你不联网 → 汇率只能手填。建议单币种 CNY |
| A8 | **要应用锁吗？**（PIN 码 / 指纹） | 不登录 = 别人拿到手机就能看全部账目。成本不高，建议要 |
| A9 | **要拍小票 / 附图片吗？** | 涉及相机权限和文件存储，存储体积会涨得快 |
| A10 | **首页长什么样？**（A：打开就是记账键盘 · B：本月概览 + 悬浮记账钮 · C：直接是流水列表） | 决定主界面的信息架构 |
| A11 | **统计想看什么？**（可多选：分类占比饼图 / 月度趋势 / 同比环比 / 账户余额曲线 / 排行榜） | 决定报表层的查询设计 |
| A12 | **数据丢了能接受吗？** | 若不能接受 → 自动本地备份 + 换机导出的流程必须做扎实（我默认按"不能接受"设计） |

## B 类：我已定默认值（不回复 = 按这个来，不爽随时说）

| 项 | 默认值 | 理由 |
|----|-------|------|
| 币种 | 人民币 ¥，单币种，但字段预留 `currency` | 不联网拿不到汇率，多币种只能手填，先不做 |
| 默认分类 | 支出 12 个（餐饮/交通/购物/居住/娱乐/医疗/教育/通讯/人情/日用/旅行/其他）+ 收入 6 个（工资/奖金/兼职/理财/红包/其他） | 可增删改、可排序、可隐藏 |
| 金额存储 | 整数"分" | 浮点小数相加会出 0.1+0.2 的误差，记账 App 不能犯这个错 |
| 转账 | **一条记录**存（from + to 两个账户字段） | 存两条会导致统计时重复计算 |
| 时间 | 存时间戳 + 本地时区，日期可手动改 | 跨时区旅行时不会串天（虽然你大概率用不上，但先做对） |
| 删除 | 软删除（打标记，不真删） | 误删能找回；诊断面板也要靠它查数据完整性 |
| 导出格式 | JSON（完整备份，可恢复）+ CSV（Excel 能看） | JSON 保命，CSV 看图 |
| 网络权限 | **AndroidManifest 里根本不申请 INTERNET 权限** | 不是"我不联网"，是"系统在内核层禁止我联网"，这条约束才真正落地 |
| 目标系统 | Android 8.0+（API 26） | 覆盖 99% 现存设备 |
| 界面 | 中文、浅色为主 | 后期加深色模式成本很低 |

## C 类：技术侧，我处理，你不用管

- 存储引擎选型与切换（见 ADR-001）
- 数据库版本迁移（schema 从 1 升到 2 时老数据怎么保住）
- 打包成 APK 的流程（Android Studio + USB 调试）
- 日志与崩溃捕获框架
- 依赖审计（构建时自动检查有没有偷偷联网的第三方库）
