# 02 — 架构方案

## 一、约束 → 架构原则

| 约束 | 翻译成架构原则 |
|------|--------------|
| 只安卓 | 不需要跨平台抽象层，可以放心用安卓特有能力（通知、指纹、文件分享） |
| 数据全本地 | 数据写在 App 私有目录；**没有服务端、没有同步冲突、没有离线队列**——这反而砍掉了记账 App 最难的一块 |
| 不登录 | 无账号体系 → 身份就是设备本身 → 本地锁（PIN/生物识别）替代登录 |
| 不联网 | 不申请 INTERNET 权限 + CSP 锁死 + 依赖审计。**代价：汇率、自动备份到云、多设备同步全部不可能** |

> 关键洞察：这四条约束砍掉的复杂度（同步、冲突、鉴权、服务端）比它们带来的多得多。
> 这个 App 的难点不在分布式，而在**数据不能丢**和**一个人也要用得下去**。

## 二、分层

```
┌─────────────────────────────────────────────┐
│  界面层  记一笔 │ 明细 │ 统计 │ 账户 │ 我的      │
├─────────────────────────────────────────────┤
│  领域层  记账服务 · 账户服务 · 统计服务 · 备份服务    │
├─────────────────────────────────────────────┤
│  数据层  Repository 接口                      │
│          ├── 适配器 A：浏览器预览（IndexedDB）   │
│          └── 适配器 B：打包后（SQLite）         │
├─────────────────────────────────────────────┤
│  平台层  Capacitor：文件导出 · 通知 · 指纹 · 分享   │
└─────────────────────────────────────────────┘
        诊断面板：横切全部四层（见 04）
```

**为什么数据层要两套适配器**：你需要在手机浏览器里先看预览版确认布局，再打包 APK。
预览跑在浏览器（只能用 IndexedDB），成品跑在 App 里（用 SQLite 更稳）。
上层只认 Repository 接口，两边共用同一套业务逻辑——**预览看到的就是成品的行为**。

风险：**两套存储可能行为不一致**。缓解方式见"风险登记册" R2。

## 三、模块清单

### MVP（第一版就做）

| 模块 | 内容 | 备注 |
|------|------|------|
| 记一笔 | 金额键盘、分类选择（九宫格）、账户、日期、备注、支出/收入/转账切换 | 核心中的核心，打开 App 3 秒内要能记完 |
| 账户 | 现金/储蓄卡/信用卡/支付宝/微信，余额显示、增删改 | 依赖 A1 你选"要" |
| 分类 | 默认分类 + 自定义、排序、图标、隐藏 | |
| 明细 | 按天分组流水，左滑编辑/删除，按分类/账户/时间筛选 | |
| 统计 | 四视图切换：分类占比饼图 / 月度趋势 / 同比环比 / 排行榜 | A11 全选四项 |
| 预算 | 月度总预算 + 分类预算，进度条、超支标红、首页提醒 | A2 已确认要，从二期提前 |
| 备份 | 自动本地备份（每日/每周）+ 手动导出 JSON/CSV + 从备份恢复 | **必选，不是可选** |
| 设置 | 货币符号、首页默认账户、应用锁、诊断面板入口 | |

### 二期（用上了再开）

固定收支提醒、搜索、标签、报销标记、拍小票、深色模式、账户余额曲线、借还记账。

### 明确不做

AA 分摊、多币种、云同步、多人协作、投资/股票记账、发票识别（OCR 需要联网或巨大体积）。

## 四、技术选型与取舍

| 方案 | 优点 | 缺点 | 结论 |
|------|------|------|------|
| **A. Web 技术 + Capacitor 壳**（推荐） | 预览版=成品逻辑；改代码不用编译，刷新就能看；我能直接给你改 | 存储要用插件桥接；性能略逊原生 | ✅ 选它 |
| B. 原生 Kotlin + Compose | 最流畅、最省电、存储最稳 | 你看不到预览，每次改动都要 Android Studio 编译装包，返工成本极高 | ❌ 与你的工作方式冲突 |
| C. Flutter | 体验接近原生 | 你需要装 Flutter 环境；我改完你仍需编译 | ❌ 同 B |

选 A 的**核心理由不是技术更优，是它让你的反馈循环最短**：我改一行 → 你刷新浏览器 → 立刻看到。

## 五、风险登记册

| ID | 风险 | 影响 | 缓解措施 |
|----|------|------|---------|
| R1 | **手机丢失/损坏导致数据全没** | 高（不联网无解） | 每日自动本地备份 + 一键导出到外部存储/微信文件；设置页显示"距上次备份 X 天"红字提醒 |
| R2 | 预览（IndexedDB）与成品（SQLite）行为不一致 | 中 | 同一套 Repository 接口；核心用例在两套适配器上各跑一遍自动化测试 |
| R3 | 数据库升级时老数据损坏 | 高 | 每次迁移前自动先做一份备份；迁移失败自动回滚到上一版本 |
| R4 | App 被系统杀掉导致记账写到一半丢失 | 中 | 记账表单草稿自动存本地，重进自动恢复 |
| R5 | 存储写满 | 低 | 诊断面板显示占用体积；超过阈值提示清理图片 |
| R6 | 第三方库偷偷联网 | 中 | 不申请 INTERNET 权限（系统级阻断）+ 构建时依赖审计 |
